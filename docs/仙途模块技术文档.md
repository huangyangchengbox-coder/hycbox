## 1. 模块总览

### 1.1 目录与职责

### 1.2 运行形态

- 单页 canvas 2D：所有角色、妖怪、剑、特效均由代码 `ctx` 手绘，非 DOM 元素。
- 顶栏 / 弹层为普通 `view`，独立于 canvas 之上（见 `zombie.wxml` 顶部注释）。
- 主循环按帧推进：怪物状态机、剑阵演出、粒子、天气均在 `zombie.js` 内。

## 3. 妖怪建模

仙途怪物分四套机制并行：**贴图怪**、**程序化敌修人形**、**魔族 / 心魔**、**境主**。

### 3.1 贴图怪（`mobs`）

| key | 名称 | 贴图 | tint | 攻击方式 |
|-----|------|------|------|----------|
| `walker` | 腐尸 | `mobs/walker.png` | `#86efac` | melee 近战 |

| `screamer` | 嚎尸 | `mobs/screamer.png` | `#f472b6` | scream 范围嚎叫 |

**贴图命名约定**：`{key}.png`（立绘）、`{key}_atk.png`（攻击）、`{key}_w0.png` / `{key}_w1.png`（行走 2 帧）。

## 6. 已知问题与建议

1. **`void64` 无调用点（死代码）**：`_startVoidGengFormation` 定义了完整演出却无人触发。若"青竹风云诀剑"指该阵，需在 `_startGengFormation` 增加派发分支后再调整剑数。
2. **`links` 偏移硬编码 31**：与 `GENG_SWORD_COUNT` 耦合，改剑数时应同步。
3. **命名 `void64` 与实际剑数不一致**：建议随剑数重构为 `void{count}` 或语义名（如 `qingzhu_sword`）。
4. **`ASSET_VER` 需与资源实际版本同步**，否则换图不生效。
5. **单文件 11085 行**：渲染 / 战斗 / 技能 / 存档高度耦合，建议按子系统拆分（如 `render/`、`combat/`、`ult/`），降低调整形象与技能时的回归风险。
